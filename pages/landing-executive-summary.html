Executive summary

Kalshi Demo Dashboard — project overview

This site is a static dashboard for the Kalshi demo (paper-money) environment. It collects, organizes, and analyzes event-contract data across five focus topics: gas prices, elections, culture, crypto, and golf. It tracks live events until they resolve (resolved Yes or No), tracks demo-account portfolio performance, analyzes trades by type, executes trades through the documented Kalshi API, and maintains a suggestions and questions section so changes are reviewed before implementation.

Access model (verified from official docs)

  • Public market data — no API key: GET /events, /events/{ticker}, /markets, /markets/{ticker}, order books, trades, candlesticks.
  • Authenticated — API key required: portfolio balance/positions/orders/fills/settlements, order placement (POST /portfolio/events/orders), cancel, amend, and all WebSocket connections. Signing uses KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP, KALSHI-ACCESS-SIGNATURE (Ed25519 or RSA signature of timestamp + method + path).
  • Demo = mock funds: no real money at risk. Demo API keys work only against demo endpoints.

Verification status (this build)

Environmental limitation: the build sandbox cannot reach kalshi.co (outbound internet is limited to github.com, npm, and PyPI hosts). Live market values, event resolutions (Yes/No), portfolio balances, fills, and trade results were not fetched from the official Kalshi API and could not be empirically verified. Per the project verification standard, every such value is left blank and flagged unverified with a source link to the official documentation; nothing is inferred or filled in.
Credentials: no Kalshi API credentials exist in this repository and none were created or stored. Trade execution and live portfolio reads require you to supply your own demo API key. See pages/trades.html and pages/portfolio.html.
