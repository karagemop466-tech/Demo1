Paper trading & strategy analytics SIMULATION

Executes simulated trades on the five tracked categories (gas, elections, culture, crypto, golf), categorizes them by strategy and market type, and reports performance. Every simulated fill requires a displayed bid/ask with size from official demo-API data (or the verified snapshot when the API is unreachable). No real orders are sent — see “How real trading would work” below.

Strategy catalog (each trade is tagged for later analysis)

1 · Deep-favorite holdscope: crypto, gas

BUY YES when 0.92 ≤ best bid and best ask ≤ 0.98 with displayed ask size. Hold to settlement. Tests whether near-certain contracts are worth holding against event surprise and exit liquidity.

2 · Longshot lotteryscope: elections, culture

BUY YES when best ask ≤ $0.02 with displayed size. Most longshots resolve NO — the point is to measure the real hit rate instead of assuming one.

3 · Tight-spread round tripscope: golf

Instant simulated buy-at-ask / sell-at-bid when the spread ≤ $0.002 and both sides show size. Demonstrates that displayed depth is not guaranteed execution.

4 · Momentum chase (1-min candles)scope: crypto — LIVE mode only

If the last 5 traded 1-minute candle closes are strictly increasing, BUY YES at ask. Skipped in snapshot mode (no history there) — nothing is reconstructed.

How REAL demo-account trading would work (not implemented here — credential-gated)

  • Authentication uses signed API keys (Ed25519/RSA, KALSHI-ACCESS-* headers): Quick Start: Authenticated Requests · API Keys.
  • Order placement: Quick Start: Create your first order. Account reads: Get Balance · Get Positions · Get Fills.
  • A static GitHub Pages site cannot hold a private signing key safely; real trading needs a separately secured server-side signing service plus explicit risk limits (flagged on the review page). No credentials exist in this repository and none were added.
  • Rate limits apply to authenticated endpoints — see Rate Limits and Tiers.

What this page can and cannot tell you

  • Can: whether a rule would have triggered on displayed prices; simulated P&L from official marks and official resolutions; hit rates per strategy/category on DEMO data.
  • Cannot: guarantee fills (displayed liquidity ≠ execution); model fees or slippage beyond the spread rule; generalize demo results to production (demo volumes are synthetic — see Flagged for Review).
SIMULATION ONLY — no orders are transmitted. Data: official Kalshi demo API (public endpoints) or the verified snapshot; see docs/demo-data-verification.md. Not investment advice.
