What this site does now

  • Ranks captured events by estimated dollar turnover and filters to the five topics.
  • Tracks each event until every leg has a yes/no result, including events that are only partly settled.
  • Plots real captured candles with a selectable time axis and shows contracts resting at a chosen price, with the cost and slippage of taking them.
  • Provides a replay simulator so trade logic can be inspected without an account.
  • Keeps the record straight: provenance, open questions, flags.

What it cannot do here

  • No real trading or portfolio read. No demo API key or private key was supplied, so nothing was executed. The path to enable it is documented on Portfolio & trades.
  • No sub-second stream from a static page (see the WebSocket constraint above).
  • Live mode depends on your browser being allowed to read the demo host cross-origin; if the request is refused, the dashboard says so and falls back to the snapshot instead of pretending.
  • Not investment advice. Demo prices are simulated.

regenerate the snapshot from anywhere with network access, same schema, nulls preserved, cursor-following; --check re-probes the documented API quirks and --dry-run writes nothing.

pre-commit gate: every internal link and anchor, every mount id the renderers expect, every docs.kalshi.com URL against the official index, and source coverage in the snapshot.
tools/kalshi_sign.py
reference signer for the KALSHI-ACCESS-* headers (Ed25519 built in, RSA-PSS via cryptography); --self-test reproduces the RFC 8032 vectors and confirms the query string is excluded from the signed payload. It refuses to send unless KALSHI_ALLOW_LIVE=1 is set.
