Flagged for review

Published rather than hidden. These are the places where the data is thin, a claim could not be confirmed, or the API behaves in a way that will bite whoever extends this. None of them block the site; all of them should be read before acting on a number.

Reading convention. unverified means “we could not confirm this from an official source, so no value is shown”. derived means “this number is computed by us, not published by Kalshi”. A blank cell is deliberate, never an oversight.

FL-1 “Highest dollar amount” is not an API field. Markets report contract counts (volume_fp, volume_24h_fp, open_interest_fp); dollars are computed here as volume × last price, which prices a lifetime of trading at the final print. Rankings are therefore directional, not audited turnover. derived Get Markets schema · live payload Either sum price × count over GET /trades per event and cache it (S-1), or accept the proxy in writing and keep the estimate label in every header.
FL-2 CORS from a browser to the demo host is unverified. If Access-Control-Allow-Origin is absent, the dashboard's live scan silently fails for every visitor and only the snapshot renders. Response headers were not observable in this environment. unverified click Scan live API now — the banner reports the real outcome per browser One click on the dashboard from your network, or a curl -i preflight showing the header. If it fails, the answer is a read-through proxy, not a redesign.
FL-3 Streaming and account features are structurally out of reach for a static page. The WebSocket docs state the connection itself requires authentication even for public channels; browsers cannot set handshake headers, and no page should hold a private key. blocking WebSocket Connection · API keys A signed proxy (or a desktop/Node client). Then the dashboard can consume a bridge endpoint and “live” means streamed rather than polled.
FL-4 Seconds on the X axis cannot come from REST at all. period_interval accepts only 1, 60 and 1440 minutes, ≤5,000 periods per call. The “seconds” option on this site therefore shows 60-second buckets of 1-minute candles and says so. partial delivery Get Market Candlesticks Accept 1-minute as the floor, or fund the WS bridge and use trade/ticker/cfbenchmarks_value_5hz.

FL-6 GET /trades could not be retrieved in this session, with either ticker= or market_tickers=. FL-7 The collector in this repo has never reached the API from here. The sandbox blocks all egress except package and Git hosts (three direct attempts failed at TLS with exit 35), so verified-desk/tools/refresh_snapshot.py has only had its failure paths exercised: --check and --dry-run both exit cleanly and write nothing, which is the behaviour that matters when a capture dies mid-run. verified-desk/tools/kalshi_sign.py is a different case — its Ed25519 is verified offline against the published RFC 8032 vectors, so the algorithm is proven here even though Kalshi's verifier has never seen a request from it. verified-desk/tools/check_links.py runs fully offline and passes. untested path demo environment docs (an environment fact, not a Kalshi claim) One run of python3 tools/refresh_snapshot.py --check followed by python3 tools/refresh_snapshot.py on any machine with ordinary egress; the collector logs every request it makes, so a partial failure is visible in request_log rather than silently shrinking the file.
FL-8 Partial captures are visible as gaps. volume_fp for KXPGATOP40-THOC26-ABHAT is null because the response chunk ended mid-object, and the golf settled listing spans 81 chunks of which only the first was read. Golf coverage here is therefore two events, not the tournament. incomplete the paged query The refresher follows cursors to completion; the UI already marks the affected event's dollar total with a floor badge instead of hiding it.
FL-9 This repository is being written by several agent sessions at once, and the collisions were real. The base commit contained only README.md with the text # Demo1. While this desk was being built, four other sessions merged their own sites into main, and each also wrote root-level index.html, dashboard.html, markets.html, portfolio.html, questions.html, suggestions.html and flagged.html — the same filenames this desk had chosen. Merging naively would have overwritten someone else's landing page or hidden this one. How it was resolved at integration: the whole desk (pages, assets/, data/, tests/, tools/) moved under verified-desk/ with its own landing page, and the root index.html keeps its hub role with one additive section linking here. No file owned by another session was deleted or rewritten. GitHub Pages remains a legacy Jekyll build of main at /, so .nojekyll must stay (it does) and any file beginning with an underscore would be stripped from the published site. process main commit history · Pages publishing source Nothing to clear — this is the record of how the collision was handled. Unifying the five desks under one navigation is a decision for the repo owner, not something to do unilaterally in an integration commit.
FL-10 Silent-parameter behaviour will mislead extensions. GET /series?limit=5 returned the whole category; an unknown tags= value returns {"series":null} rather than an empty list; GET /events?with_daily_volumes=true was accepted and ignored. None of these raise an error you could catch. trap Get Series List (no limit parameter exists) Already encoded: null-vs-empty handling and unit tests for both branches. Keep validating parameter names against the OpenAPI blocks rather than trusting a 200.
FL-11 Reads are cached and event status is coarser than market status. At 11:18Z the open-events query still showed a market whose close_time was 11:15:00Z as active; the ballot event appeared under status=open with three of four legs finalized. Polling event listings for settlement timing will be wrong by seconds to hours. accuracy “prices, sizes and status can lag … by several seconds” Poll the single market (or the WS market_lifecycle_v2 channel) inside the close window, and treat result — not event status — as the settlement signal, which this tracker does.
FL-12 Fee-schedule extraction is lossy. The PDF's non-standard-fee table came out of text extraction with columns interleaved, so only the formula, the maker coefficient, the “no settlement fee” line and the KXAAAGASM multipliers are quoted here. Multipliers for other series are not published on this site rather than guessed. partial fee schedule PDF · upcoming changes page (linked from the PDF, not yet checked) Confirm per-series multipliers from GET /series/{ticker} (fee_type, fee_multiplier) — the API is the better source anyway, and it is already in the engine.
