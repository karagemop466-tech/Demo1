WebSocket channels (verbatim enum)

orderbook_delta, ticker, trade, fill, market_positions, market_lifecycle_v2, multivariate_market_lifecycle, communications, order_group_updates, user_orders, cfbenchmarks_value, cfbenchmarks_value_5hz, pyth_value, ebattle_scores.

  • Subscribe: {id, cmd:"subscribe", params:{channels:[…], market_ticker|market_tickers:[…]}}; one subscription per channel per connection — re-subscribing adds markets to the existing sid rather than creating a second feed.
  • Sub-second price views come from cfbenchmarks_value_5hz (5 Hz), which is also the settlement reference for the crypto series — the same number the rules use.
  • A rejected handshake returns HTTP 429 too_many_requests for both “too many concurrent connections” and “opening too fast”, so reconnect with exponential backoff.
  • Source: WebSocket Connection.

Limits, pagination, accuracy

  • Tokens, not windows. Most requests cost 10 tokens; the tier sets a per-second refill; GET /account/endpoint_costs is authoritative for exceptions. Rate Limits and Tiers
  • Read/write buckets are per operation, not per verb; GET /portfolio/balance has its own bucket (1/s on Basic-Advanced). Unauthenticated public requests have separate limits of their own.
  • 429 has no penalty and no Retry-After; the bucket keeps refilling and “your next request succeeds once the balance covers its cost”.
  • Cursors are opaque. Pass them back unchanged; a cursor that cannot be decoded is silently ignored and returns page 1 with no error; stop when the returned cursor is empty. Understanding Pagination
  • Rows can repeat or vanish mid-scan when a market's close time changes during a close-time-sorted page walk — “deduplicate by ticker”, which Kalshi.scanEvents does by event_ticker.
  • Reads lag. Responses are cached briefly so “prices, sizes and status can lag the exchange by several seconds”, and filtered listings lag longer than a single-market read.
  • Historical cutoff. Markets settled before it move to GET /historical/markets and its candlestick/fills/positions twins — relevant as soon as this snapshot ages. Historical Data

Fixed-point representation why the maths is written the way it is

Prices and counts arrive as decimal strings ("0.2900", "385.82") to support sub-penny pricing and fractional contracts — see Fixed-Point Representation. The engine therefore (a) parses through one helper that maps ""/garbage to null rather than 0, and (b) normalises every computed dollar amount to micro-dollar precision before display, because 100 × 0.29 is 28.999999999999996 in IEEE-754. Both behaviours are asserted by tests.

Every market row also carries price_ranges with start/end/step; the 15-minute crypto market uses a tapered grid (0.0010 below 0.10, 0.0100 between, 0.0010 above 0.90). Any order price must sit on that grid or it is rejected 400 invalid_price.
