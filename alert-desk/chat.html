How to read a message

  • ▲ / ▼ + dollar delta — direction and size of the move. last trade means the official last traded YES price; quote mid means (yes bid + yes ask) ÷ 2, a derived value shown only when no trade exists, and labelled as derived.
  • API ↗ — the exact official request URL that produced the numbers (opens the raw JSON).
  • Event ↗ — the official Kalshi venue page for the event (kalshi.com/events/<event_ticker>, pattern verified 2026-11-20).
  • News lead ↗ — a news search, never a verified cause: the API has no causal field, so no message asserts what caused a move (repo flag F-17). Treat it as a starting point for your own reading.
  • RESOLVED — the exchange returned result (yes / no; scalar is also possible per market lifecycle ↗). We only show what the API returned; we never infer an outcome.
  • snapshot chip — message came from the committed collection (timestamped); live chip — observed by this page polling the demo API right now.

Limits, in plain words

  • Demo venue. Mock funds; prices and behaviour may not reflect real markets ↗.
  • Bounded live scan. One page of GET /markets?status=open&limit=1000 per poll (newest first) — the same bound the other desks publish. Older open markets beyond that page are not watched until they re-appear in a later page.
  • REST polling, not WebSocket. The documented WebSocket handshake requires signed API-key headers even for public channels (quick start ↗), and no credentials exist in this repo — so this page polls REST and backs off on 429 (rate limits ↗). REST responses are cached a few seconds by the exchange (Get Markets ↗).
  • Resolution watching lasts while this tab is open. Markets previously seen in the open list that disappear are re-checked individually (up to four due checks per poll, with per-market backoff) until the API returns a YES, NO, or scalar result. An active market can also disappear from a bounded first page; disappearance is not a resolution. The watch queue is not persisted across reloads or closed tabs, and markets never seen on that page are not watched. A result never observed is left unverified — see the resolved snapshot instead. Get Market ↗
  • Topic rules are keyword rules, same published patterns as the consolidated desk, not an official Kalshi taxonomy. Weak/known false matches (e.g. KXWTI crude oil) are excluded — repo flag FL-05.
  • No credentials, no orders. This page reads public market data only. It never stores a key and never sends an order.
