Demo account · credentialed surface

Portfolio

Balances, positions and fills on the Kalshi demo account are real API objects — and they are all behind request signing. This page shows exactly which calls produce them, why they are blank here, and what you would need to supply to fill them in.

Blank on purpose. No demo API key exists in this repository, and a public static site must never carry one: anyone who can read the page can read the key. The tables below are therefore empty rather than estimated.

Signing, as documented

  1. Create a demo key pair on the demo exchange (official tutorial); downloads the private key once.
  2. Sign timestamp + METHOD + path with Ed25519 or RSA-PSS/SHA-256 (signing guide).
  3. Send KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP, KALSHI-ACCESS-SIGNATURE headers. No header, no data.

What would unblock the real account

  • A demo key pair, stored as repository Actions secrets and used only inside a workflow — never committed, never shipped to the browser.
  • A read-only workflow that calls /portfolio/balance, /positions and /fills, writes a JSON snapshot, and lets this page render it (the repo already has an example pattern in tools/account_worker.py).
  • For real orders, an explicit decision on risk limits and an auditable order log — see FL-02.
