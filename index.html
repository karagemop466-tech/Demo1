Start here — the trading desk

Live alert tapes (two scrolling chats)Every swing of ≥ $0.10 in either direction across the five topics, and a second chat with only the high-ROI screen’s picks. Auto-starts, polls the official demo API in your browser every 15 s, and never places an order. Live trade desk — alert chats, chart, paper tradingTwo scrolling chats for every move of at least $0.10 (one unfiltered, one filtered by a published fee-aware screen), a seconds/minutes/hours price chart, order-book depth, resolution tracking to YES/NO and simulated-trade analytics. Public endpoints only, no key (session 87015421). Two-chat alert feed with snapshot fallbackChat 1 every ≥ $0.10 swing, Chat 2 the markets its simulated model likes by two disclosed rules; fed by the live demo trades tape, falling back to the committed snapshot when the browser cannot reach the API (session 0ad208bf). Primary live market deskFive-topic demo-market scan, price-history views, reported order-book liquidity and market-resolution status from the official API. Price chart & liquidityPrice over time from official 1-minute, 1-hour and 1-day candles (no seconds resolution exists on the REST endpoint), and the contracts bid at each price. Live markets tableOpen markets, ranked by computed 24-hour notional. Each topic page shows up to 60 rows, with the API source of each row. Price swing alerts (two scrolling chats)Consecutive official candle closes compared at the selected threshold (default ≥ $0.10 either direction); Chat 2 ranks by a disclosed relative-move heuristic. Official API + venue + news-search links per message; cause unverified. (page and 23-check regression suite by sessions d973ced5 / b62e8188; the data-pipeline fix behind it is this session’s.)

The ≥ $0.10 two-chat requirement is implemented five times on this site, because five sessions built it in parallel against the same brief: alerts-live.html (this session: browser polling, five-gate screen, model spec), alerts.html (committed candlestick capture, sessions d973ced5 + b62e8188), alerts/index.html (its own generated feed and QLM score), trade-desk/ and alert-desk/. All five share the $0.10 threshold and none places an order — but each measures a “move” against a different price (best ask, last print, candle close), so a flag on one page need not appear on another at the same minute. Nothing was deleted; S16 asks you to pick the survivor. Data freshness: snapshot/*.json is the source of the counts below (collected 2026-11-20T11:43:59Z), and CI refreshes docs/data/*.json every 15 minutes — its last run and error list are public in docs/data/run_log.json.

Alerts, jumps and resolutions

Candlestick jump detector (≥ $0.10)Flags moves between official candle closes and links each row to its API request and venue event page; no cause is asserted. Jump scanner with news-search leadsSelected high-volume markets, one-minute changes and potential-source searches. A search result is a lead, not proof of cause. Live resolution trackerFollow open markets until Kalshi returns a YES/NO result; the browser-local watch log is not a server archive. Resolved outcomesMarkets with a result set by the API (yes or no; scalar results are also possible), with settlement fields.

What changed on this page

The previous landing page had hand-typed figures. Checked against the official API on 2026-11-20. Full line-by-line record: verification page ↗.

  • Culture is not empty. The previous page said there was no verified open culture market. The official demo API returns open culture markets: KXRT-FUR-85 has status: active (retrieved 2026-11-20). The snapshot holds 191 open culture markets.
  • Demo host, not production. The previous 15-row table came from the production host external-api.kalshi.com. This dashboard uses the demo host you requested, external-api.demo.kalshi.co, which the official documentation recommends for demo (API environments ↗).
  • "Resolved" was overstated. The previous total of 2,469 included 352 markets that are closed but have no result yet. Those are now listed separately.
  • Counts are generated, not typed. The topic numbers above come from the snapshot files and reconcile to the snapshot totals.
