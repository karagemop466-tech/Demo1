Data definitions and official references

The links below are Kalshi's official references for the API concepts used by the dashboard. Each linked market row on the category pages also carries its specific source request.

What you are viewingHow to read itOfficial reference
Market listings Market rows come from the selected API request; the page shows its source and snapshot time. Get Markets API reference ↗
Dollar ranking The live desk computes estimated 24-hour notional from available volume and price inputs; this is not an official Kalshi USD-volume field. See RANK-01 for the limitation. Get Trades API reference ↗ · Desk methodology
Price changes Alert methods and sampling windows differ by desk. A price jump alone does not establish its cause. Get Trades API reference ↗ · Get Market Candlesticks ↗
Order-book depth Displayed quantities are contract counts at reported book levels; an empty level is not a confirmed fill. Kalshi returns bids only — the opposite side is implied at 1 − price. Order-book responses ↗
Market outcomes Only the API-reported result is displayed; closed markets with no result are not treated as resolved. Settlement pays $1 per contract on the winning side. Market lifecycle ↗ · Market settlement ↗
Demo environment Demo prices, liquidity and simulated fills are test-environment data and may not reflect production markets. Demo environment notice ↗
Live updates This public site polls REST instead of opening a WebSocket, because the documented handshake requires signed requests and no key is stored here. WebSocket quick start ↗

Trader's guide

One page that maps which desk does which job, what every number means, and where each fact comes from.

Several desks solve the same requirement. The ≥ $0.10 dual-chat rule, the price chart and the resolution watch were each built more than once by sessions running in parallel against one brief. Nothing was deleted: the trader path above is the designated working route, and the page directory lists every implementation with its own description. Each desk measures a “move” against a different price (best ask, last print, candle close), so a flag on one desk need not appear on another in the same minute.
