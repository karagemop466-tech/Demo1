Suggestions — review before anything is implemented

This section is dedicated to proposals that would improve decision-making on the site. Each item is reviewed here first: Accept → Reject → Defer, then accepted items are ordered into an implementation path (the "best path" picker at the bottom). Nothing is implemented without an explicit decision recorded in this browser. Auto-suggestions are computed live from official API values and labeled with the data they came from.

Implementation path (choose the best path)

Order the accepted suggestions into a sequence, then commit the choice. The path is stored locally and shown on this page; implementation work happens only for items on the chosen path.
Recommended default ordering logic: (1) unblock data (transport/credentials), (2) fix measurement definitions (ranking metric), (3) deepen analysis (strategy tagging), (4) automation (alerts). This ordering is itself a suggestion, not an implementation.

How decisions flow

1 · Discover

Auto-suggestions are derived from live values (spread, depth, connection state, resolution activity) — each shows its input values.

2 · Review

A reviewer marks each suggestion Accept / Reject / Defer with a note. Decisions persist in this browser only.

3 · Choose path

Accepted items are ranked into an implementation path; the chosen path is the only queue that may be implemented.
