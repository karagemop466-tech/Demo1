Kept simple on purpose

What was deliberately left out

  • No order entry at all. Placing orders from a public static page requires holding an API private key in the browser, which is unsafe. Simulated only.
  • No logged-in portfolio. The demo portfolio endpoints need a signed key. Rather than fake balances, those panels are absent and the reason is written on the page.
  • No causal claims. Alert rows link the venue's own settlement sources plus a news search. No headline is ever asserted as the cause of a move.
  • No auto-refresh loop that never stops. Polling has a minimum gap, backoff on 429/5xx, and stops after repeated failures instead of hammering the venue.
  • No second charting library. One ~300-line SVG chart keeps the page fast, printable and auditable.

Next steps, in priority order

  1. Move the poll loop to a server-side collector with an API key, then stream to the page over Server-Sent Events; the official WebSocket remains the lowest-latency option but needs that signed connection.
  2. Persist every jump and resolution server-side so history survives a browser reset (today the ledger is local).
  3. Extend calibration to entry-to-settlement paths from the trades tape, so the screen can be scored on realised returns instead of base rates.
  4. Add per-series fee overrides from the schedule, which the current fee function does not model.

Statuses are checked by a test: node trade-desk/tests/links.test.mjs verifies every implemented suggestion links to a page that exists.
