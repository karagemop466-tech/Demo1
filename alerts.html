How this page stays honest

Data path

  • Base URL https://external-api.demo.kalshi.co/trade-api/v2 — the demo endpoint named in the brief and in API environments · demo environment.
  • Three requests per cycle, whatever the watchlist size: GET /markets?tickers= (quotes), GET /markets/orderbooks?tickers= (depth, ≤100 tickers), GET /markets/trades?limit=1000 (print tape).
  • Asks are not returned by the API. A YES ask is derived from the best NO bid as $1.00 − price, exactly as the order-book docs describe; each line says which side it was derived from.
  • Price = YES contract price in dollars, X axis = time (1-minute candles from the candlesticks endpoint; it has no sub-minute period, so “seconds” only exist in this browser between polls).
  • Resolution: a watched market stays on the tape until the API returns result; the line then shows YES / NO (or scalar) with its event record link — settlement docs.

Limits, stated plainly

  • This is polling, not streaming. The WebSocket API would stream, but its handshake requires a signed authenticated connection, and a browser cannot set those handshake headers — so a credential-free page cannot use it.
  • REST reads are cached. Get Markets states prices, sizes and status “can lag the exchange by several seconds”. The tape is a demo-data monitor, not a matching engine.
  • Unauthenticated traffic is rate-limited separately (rate limits); a 429 makes this page back off exponentially and say so in the banner.
  • No orders are placed. The tape is read-only by construction — there is no key in the page and no write call in the script. Simulated trading lives on paper trading, the strategy engine and sim-desk, which trades on this same tape shape in CI.
  • Demo venue. “The price and behavior of markets in the demo environment may not be reflective of those in real markets” (docs). Thin books, zero volume and placeholder-like values are shown as blanks, never filled in.
