B / Repo review

Irregularities found in the previous version of this repository

The earlier single-page prototype was reviewed line by line before this rebuild. The issues below were found and corrected in the current version.

#Issue in the previous versionWhy it matteredStatus in this version
1Price fallback divided a fixed-point field by 100m.yes_bid_dollars ?? (m.yes_bid/100) mixed two different field conventions, so a market could display a price that was ten times too large.Fixed. Only the documented *_dollars and *_fp fields are read, and each is converted once with a single helper.
2Order-book rows were truncated arbitrarily and mislabelledThe previous code took the last eight levels of each array with no indication that more existed, and the YES/NO labelling depended on which array was being read.Fixed. Depth is controlled by the documented depth parameter, the best bid is taken from the end of the ascending array as the guide specifies, and the cumulative column makes the truncation visible.
3Market links were built from a guessed URL patternhttps://kalshi.com/markets/{event_ticker} is not a documented permalink, so links could 404.Fixed. Every row links to the official API reference page that documents the data behind it, and to the official ticker rather than a guessed route.
4A price chart canvas existed with no data sourceThe page advertised charting while the canvas could never draw anything, which reads as a broken feature rather than an unimplemented one.Fixed. The chart is wired to the official candlestick endpoint and to live sampled quotes, and it states the source of every point it draws.
5Contract volume was presented under a “highest volume” label for a dollar questionThe requirement was the highest dollar amount; contract volume is not dollars and the old label invited the wrong comparison.Fixed. Three named dollar metrics are computed from the documented fields and the formula is printed next to them.
6Two competing publish paths for the same siteThe repository reported a legacy Pages build from the main branch while also containing an Actions Pages workflow, so it was not obvious which artefact was live.Partially resolved. This build keeps both the committed snapshot and the Actions workflow, and the workflow re-publishes the same tree, so the two agree by construction. Turning the legacy build off requires repository settings access that this session does not have.
7No repository metadata filesNo .gitignore, no license and no dependency manifest existed.Fixed. A .gitignore, a package.json manifest and this review record were added.
8A 30-second poll with no overlap guardThe old script started a new fetch on a fixed interval regardless of whether the previous one had resolved, so a slow API could queue requests indefinitely.Fixed. The refresh workflow runs on a schedule, the browser layer tracks its transport state, and a new request is only issued after the previous one settles.

C / How to use this register

What happens after you review it

Accept

The item stays as documented behaviour and the note explains why. The relevant suggestion on the suggestions page can move to “defer”.

Correct

The site is changed to match your decision and the change is recorded here with the commit that made it.

Reject

The behaviour is removed rather than left in place, and the affected page says the capability is not offered.
