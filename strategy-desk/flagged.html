⚠ Flagged for Review

Irregularities, limitations, and unverified items found during this work. Published here for your review; per the brief, these do not block the merge — they are recorded for post-launch review and change requests. Each item links its evidence.

IDSeverityItemEvidence / sourceImpactProposed resolution
F1HIGHReal demo order execution is not possible from a static site. Trading/portfolio endpoints require signed authenticated requests (API key + Ed25519/RSA private key). No credentials exist in this project (none were provided), and secrets must not be embedded in a public repo or browser. Therefore the portfolio is a clearly-labeled SIMULATOR that fills against live demo prices — no real Kalshi orders are placed. Auth requirements (official) ↗ Portfolio P&L is simulated, not the demo account’s actual ledger Approve S1 (server-side credential proxy, e.g. Cloudflare Worker with secrets) on the Suggestions page, then wire POST /portfolio/orders + GET /portfolio/balance|positions|fills through it
F2MEDIUMBuild sandbox cannot reach *.kalshi.co (outbound restricted to github/npm/pypi). Live API verification could not be executed from the build environment; it runs in the user’s browser instead. CI cannot assert “API returns X”. Environment restriction (curl to external-api.demo.kalshi.co → no connection); see official endpoints ↗ Automated tests validate code + fixtures only; live data checks happen at runtime in the browser Open the published site and confirm the LIVE badge; optionally run a scheduled GitHub Action from ubuntu-latest (unrestricted) to smoke-test endpoints (S5)
F3MEDIUMTopic→series mapping is not offline-confirmable. Candidate slugs (e.g. KXGASUSD for gas) are committed as candidates only; each is runtime-verified via GET /series/{ticker} and excluded if unverified. The runtime scan also discovers series automatically by official category field. S-13 · data/series-map.json ↗ A topic may temporarily show “unverified / no markets” until the runtime check sees it Review the verified-series pills on Live Markets after deploy; prune wrong candidates
F4LOW“Dollar volume” is an estimate. Kalshi reports volume in contracts; no dollar-volume field exists. Tables compute Σ(contracts × last price) and label it “Est. $ volume” everywhere. Get Markets field reference ↗ Rankings could differ slightly from Kalshi’s own “top markets” ordering If you prefer a different ranking metric (open interest / liquidity / raw contracts), say so in Q4 (Suggestions)
F5LOWDefensive field normalization. Fixed-point field shapes in orderbook_fp and candlestick responses are normalized defensively (string/object/number forms). If the API returns an unexpected shape, the UI flags it rather than mis-rendering. Exact payload shapes could not be captured in the sandbox (F2). Orderbook reference ↗ · Candlesticks reference ↗ Unusual responses surface as explicit flags, not wrong numbers First live session: confirm depth bars and candle overlay look correct; report any flag badge
F6LOWRepository was empty before this work. The repo contained only a stub README.md (“# Demo1”, single commit 4a225ce “Initial commit”). No pre-existing data, tables, or code existed to audit line-by-line; the repo review therefore covers all files created in this session. Initial commit ↗ None — documented for completeness None needed
F7LOWDemo lineups can be sparse. Some topics (e.g. golf or culture) may have no open demo markets at a given time; tables then show the explicit empty-state message rather than stale or invented rows. Demo environments also reset/rotate mock data. Demo environment docs ↗ Empty tables on some days are expected behavior, not bugs If persistent, consider S8 (production read-only toggle) via Suggestions
F8MEDIUMGitHub Pages must be enabled with “GitHub Actions” as the source for the deploy workflow to publish. If it isn’t, the workflow fails at the deploy step. This cannot be checked from the sandbox; the PR merge record in COORDINATION.md will state the outcome. GitHub Pages publishing source docs ↗ Possible first-deploy failure If deploy fails: Settings → Pages → Source = “GitHub Actions”, then re-run the workflow; per the brief, failures are fixed and retried until live
F9LOWWS subscribe-message shape not fully pinned. The analytics page attempts the official demo WS and falls back to REST polling (3 s) with an explicit transport badge. The subscribe payload is sent empty; if the expected shape differs, REST still delivers all shown values. WS endpoints (official) ↗ Chart cadence may be 3 s instead of true tick-by-tick if WS handshake fails Capture one live WS session (S2) and pin the exact subscribe schema
F10LOWDocs-path precision. A few cited docs paths (fee schedule, rate limits) are listed from the docs index and may move as Kalshi reorganizes docs. Root links are provided so the fact stays traceable. docs.kalshi.com index ↗ Minor: a citation link may 404 over time Re-check cited paths during the next review cycle
