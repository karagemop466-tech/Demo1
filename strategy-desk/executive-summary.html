Kalshi Demo Tracker — Executive Summary

Collects, organizes, and analyzes Kalshi demo-environment prediction markets. Live tracking of the highest-dollar events across gas prices, elections, culture, crypto, and golf; resolution (YES/NO) tracking through settlement; price analytics; and a clearly-labeled simulated portfolio for trade-strategy analysis.

1 · Objective

Build a live, interactive dashboard on GitHub Pages that:

  • Tracks the highest-dollar live events on the Kalshi demo exchange, restricted to five topics: gas prices, elections, culture, crypto, golf → Live Markets
  • Follows each event through resolution — showing whether it resolved YES or NO (official result field: yes | no | scalar) → Live Markets, resolution table
  • Charts price movements with X = time (seconds / minutes / hours window) and Y = contract price in cents, plus orderbook depth: current liquidity and contracts available at each price → Analytics
  • Tracks portfolio performance on the demo account, categorizes trades, and builds strategy analytics → Portfolio (SIM)
  • Surfaces suggestions and open questions that must be answered before decisions, with a review workflow → Suggestions & Open Questions

3 · Method & verification discipline

  • Nothing is invented. Every displayed market value comes from a live call to the official demo API at view time. Values that cannot be fetched are left blank and flagged unverified.
  • Series mapping is runtime-verified. The topic→series map (gas/elections/culture/crypto/golf) is only trusted after GET /series/{ticker} returns 200; mismatches are excluded and shown on the Flagged page. Candidates live in data/series-map.json.
  • “Dollar volume” is an estimate. Kalshi publishes volume in contracts, not dollars. The tables compute Σ(contracts × last price) and label it Est. $ volume everywhere.
  • Fees use the official formula fee = ⌈0.07 × C × P × (1−P)⌉ (next cent up), cited in the app and on Sources.
  • Portfolio is SIMULATED and loudly labeled — see Flagged item F1 for why real order placement needs a server-side credential proxy.
  • Parallel-session coordination is maintained in COORDINATION.md (task board, claims, sources, irregularities).

4 · Key findings & irregularities (headline)

  • F1 (flagged): Real demo-account trade execution requires signed authenticated requests. A browser-only site cannot hold private keys, so the portfolio module simulates execution against live demo prices. To execute real trades, a small server-side proxy (e.g., Cloudflare Worker) holding demo API credentials is required — costed and proposed on the Suggestions page. Review
  • F2 (flagged): Sandbox/build environment network policy blocks *.kalshi.co, so live verification happened in-browser; automated tests fall back to fixture checks. Review
  • F3 (flagged): Topic→series mapping cannot be fully confirmed offline; the site self-verifies at runtime and displays anything unconfirmed as blank + flagged. Review
  • Observation: The repository contained only a stub README.md (“# Demo1”) before this work — no pre-existing data to audit. Review

5 · How to use

  1. Live Markets — pick a topic tab; tables auto-poll every 20 s and sort by estimated dollar volume. Click any row’s Chart ▸ to open analytics.
  2. Analytics — choose a market; pick a time window (15 s / 1 m / 10 m / 1 h / 6 h / 24 h); watch the live price line, and read the orderbook depth (contracts available at each price, YES and NO sides).
  3. Portfolio (SIM) — place simulated orders on live demo prices, assign a strategy tag, and review the analyzer (P&L by category and strategy, win rate, fees). Export JSON anytime.
  4. Suggestions — review open questions with current best-known answers, then triage proposed improvements (accept/defer) before implementation.
