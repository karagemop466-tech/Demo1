What could not be verified here

  • Live API calls from the build sandbox. This environment has no route to *.kalshi.co, so the live poller's behaviour against the real API was checked by unit test and code review, not by a live request. The page shows the request it tried and falls back to the committed feed.
  • Account data. No Kalshi demo API key exists in this project, so balance, positions and fills are blank everywhere and no order was ever sent. Reading them needs a signed request, which needs a key: API-key guidance ↗.
  • Realised ROI. The score in the model card is a ranking. Realised ROI needs settled markets, which the demo exchange produces over weeks; the simulation ledger pages track that separately.
